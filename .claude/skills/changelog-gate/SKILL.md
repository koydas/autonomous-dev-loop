# changelog-gate

## When to Apply

Any PR you open or push to that touches **any** of these file categories:

- `scripts/*.mjs` — top-level entrypoint scripts (NOT `scripts/lib/*.mjs` or `scripts/tests/*.mjs`)
- `docs/adr/NNNN-*.md` — ADR files (four-digit prefix, under `docs/adr/` only)
- `.github/workflows/adl-*.yml`, `templates/consumer/*.yml`, `docs/workflow-interface.json` — what a repository using the pipeline from elsewhere depends on (ADR-0045); a change a caller can notice goes under `### Breaking` (see `docs/releasing.md`)

CI workflow `changelog-check.yml` enforces this gate and will fail the PR if the requirement is not met.

## Expected Behavior

1. Confirm whether any changed file matches one of the trigger categories above. If none matches, skip this skill — no changelog update is required.

2. Add one unique `changes/<issue-number>-<slug>.md` file for this PR; distinct PRs for the same issue use distinct slugs.

3. Start the fragment with one `### Added`, `### Changed`, `### Fixed`, or `### Removed` heading and at least one `- ` bullet describing the change.

4. Include the relevant ADR or issue reference in the bullet when applicable.

5. Commit the fragment with the triggering change. Never modify root `CHANGELOG.md` in feature PRs. For an exempt change, use a `No-Changelog: true` line in the PR description.

**Exact trigger rules (from `scripts/lib/changelog_checker.mjs`):**

- Entrypoint regex: `/^scripts\/[^/]+\.mjs$/` — matches `scripts/foo.mjs` but NOT `scripts/lib/foo.mjs` or `scripts/tests/foo.mjs`
- ADR regex: `/^docs\/adr\/\d{4}-[^/]+\.md$/` — matches `docs/adr/0019-my-decision.md`
- Reusable workflow regex: `/^\.github\/workflows\/adl-[^/]+\.yml$/`; caller template regex: `/^templates\/consumer\/[^/]+\.yml$/`; snapshot: exactly `docs/workflow-interface.json`

## Constraints

- Do not modify `scripts/lib/` or `scripts/tests/` files and consider yourself exempt — those files are not trigger files.
- Do not add a generic placeholder bullet like "- Updated something". The entry must describe the observable behavior change.
- PRs that add a new ADR file must themselves include a changelog entry — this is intentional and self-referential.
