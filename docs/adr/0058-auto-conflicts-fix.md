# ADR-0058: Auto conflicts-fix: a PR that conflicts with its base is merged forward, by escalating resolvers

- **Date:** 2026-10-25
- **Status:** Proposed

## Context

A PR that conflicts with its base is invisible to the loop. `pull_request` events run on the merge ref, which does not exist while the PR is `dirty`, so review, CI and auto-fix go silent; the only trace is a runbook line (branch `ai/issue-<N>` with conflicts: delete it by hand, re-apply `ready-for-dev`). The commonest causes are structural, not semantic: two PRs append to `CHANGELOG.md` under `[Unreleased]`, two PRs take the same ADR number and add a line to `docs/adr/README.md`, a lockfile moves. Auto-fix on a stale base also produces a patch that no longer applies, so a conflict must be resolved **before** the review → auto-fix loop continues.

## Decision

**A. Detection.** `scripts/detect_conflicts.mjs` lists open PRs (`gh api --paginate`) and reads `mergeable_state`. `dirty` is a conflict; `null`/`unknown` is retried a bounded number of times, then skipped (never treated as clean, never as conflicting). Triggers: `push` to the default branch (a base move is how most conflicts are born), `pull_request: synchronize`, and a scheduled sweep as a safety net. GraphQL → REST fallback per [ADR-0011](./0011-graphql-rest-fallback.md); output carries `source`. Label `merge-conflict` (`config/labels.yaml`) is set while conflicting and cleared when clean.

**B. Scope: every open PR.** `ai/issue-*` branches and human branches alike. A fork PR is fixed only when `maintainer_can_modify` is true; otherwise it is escalated (D), never skipped silently.

**C. Resolution is a ladder; each rung runs only if the previous one left conflicts.** The fix is a **merge of the base into the head** (`git merge`), never a rebase, amend or force-push. One merge commit: `fix(ai): resolve merge conflicts with <base>@<sha7>`.

| Rung | Mechanism | Writes |
|---|---|---|
| L0 | `git merge`; clean result (stale `dirty`, base moved again) | none by us |
| L1 | Deterministic resolvers, pure and tested: lockfiles regenerated by the package manager, never edited | derived |
| L2 | LLM resolves the remaining conflicted files, one hunk set per call, with both sides, the merge base and the PR's issue/description | conflicted hunks only |
| L3 | Escalation: `needs-human`, a comment naming the files, the rung that stopped and why | none |

**D. L2 contract.** The model returns resolved **hunks**, not whole files (the whole-file contract of [ADR-0029](./0029-autofix-deterministic-write-guard.md) is wrong for conflicts: it would let the model rewrite the non-conflicting 95 %). The script splices them into the conflicted regions and touches nothing else. Conflict markers, file contents and hunks are **data**: never interpolated into a shell, never logged (only counts, file names and rung).

**E. Domain resolvers inside L2.** Two conflict classes get a dedicated prompt section and a post-check, because they are the common ones:
- `CHANGELOG.md`: keep every entry from both sides under `[Unreleased]`, base entries first, no entry rewritten, none dropped (post-check: the multiset of top-level bullets of both sides is a subset of the result).
- ADR number collision: the base keeps its number (it is already merged); the PR's ADR takes the next free number. The renumber is **mechanical and deterministic** (`renumberAdr()`: file name, `# ADR-NNNN` title, the index line in `docs/adr/README.md`, references to the old number inside the PR's own changed files); the model only writes the **index line and CHANGELOG text** that the collision put in conflict. The model never chooses a number.

**F. Guards (preventive, before the push).**
- *Protected paths* ([ADR-0021](./0021-protected-write-path-denylist.md), [ADR-0044](./0044-protected-paths-floor-and-repo-config.md)): the base's own changes arrive in the merge commit unmodified; that is not an AI write. What is guarded is the **model-resolved** content. A conflict on a protected path is L2-eligible only for an allowlisted resolver (E: `CHANGELOG.md`, `docs/adr/`); any other protected conflicted file (`scripts/`, `config/`, `prompts/`, `.github/`, `docs/` outside E) goes to L3. The allowlist is a named, pinned list, not a general exception.
- *Write guard* ([ADR-0029](./0029-autofix-deterministic-write-guard.md)) runs on the result against the **head**: no file loses more than half its lines, tests never shrink, no module-format, exported-signature or unresolved-import change, no conflict marker left.
- *Trusted execution* ([ADR-0023](./0023-trusted-pipeline-execution.md)): resolver code and prompts come from the default branch, never from the head.
- A guard rejection aborts the merge (`git merge --abort`, nothing pushed) and escalates (L3).

**G. Budget and loop interaction.**
- Own counter, `conflict-fix-attempt-1..2` labels, separate from `auto-fix-attempt-N`; the review budget ([ADR-0034](./0034-review-fix-loop-converges.md)) is untouched. A clean (`mergeable`) PR clears them.
- Circuit breaker ([ADR-0050](./0050-circuit-breaker-review-loop.md)): the same conflict signature (sorted file list + hash of the base side) twice in a row opens it.
- When `changes-requested` and `merge-conflict` coexist, the conflict is resolved first.
- Push with `AI_PR_TOKEN` (a `GITHUB_TOKEN` push triggers no workflow); the merge commit changes the head, so `pr-review` runs on it ([ADR-0028](./0028-one-review-per-head-sha.md)). A merge that is clean but breaks CI is left to review/auto-fix, never reverted.
- Concurrency group per PR ([ADR-0020](./0020-per-pr-workflow-concurrency.md)), `cancel-in-progress: false`: the job pushes.
- A base change to `.github/workflows/` cannot be pushed by a token without the `workflow` scope: that case is L3 with the reason named.

**H. Observability.** `conflicts.start`, `conflicts.detected`, `conflicts.resolved {rung}`, `conflicts.escalated {reason}`, `conflicts.complete|error` with `duration_ms`, through `observability.mjs`; meta keys (counts, rung, reason code, file count) added to `EVENT_META_ALLOWLIST`; no hunk, file content, title or body ([ADR-0040](./0040-run-journal-and-public-run-record.md)). An `eval` suite for the L2 resolver (recorded real conflicts, minimal; the E post-checks as grader) follows [ADR-0031](./0031-eval-gates-are-a-ratchet.md).

**I. Delivery order**, each slice mergeable alone, tests/docs/CHANGELOG in the same PR (`AGENTS.md`):
1. Detection + `merge-conflict` label + one comment (read-only). 
2. L0 merge and push; attempt labels; breaker.
3. L1 resolvers (lockfiles).
4. L2 LLM resolver with the hunk contract, guards of F, eval suite.
5. Domain resolvers of E (CHANGELOG post-check, mechanical ADR renumber).

## Alternatives Considered

- **Rebase the head onto the base.** Rewrites someone else's branch history and invalidates their checkout. Rejected (repository convention).
- **Whole-file LLM output** (ADR-0029 shape). Lets the model rewrite non-conflicting code under cover of a conflict. Rejected for hunks.
- **LLM chooses the ADR number.** Non-deterministic where the answer is a function of the base. Rejected for E; the model keeps the text the collision conflicts on.
- **Blanket exception for protected paths in conflict resolution.** Erases the human-owned `docs/` rule of ADR-0021. Rejected for a named allowlist.
- **Only `ai/issue-*` PRs.** Rejected: human PRs block the same way and the base-move trigger sees all of them.
- **Revert the merge commit if CI fails.** Reverts history on a shared branch and hides the cause. Rejected.
- **Detection by `pull_request` event only.** Misses conflicts created by a push to the base. Rejected as sole trigger.

## Consequences

- ✅ Conflicts stop being silent: label, comment, and a fix or a named reason.
- ✅ The common structural conflicts (changelog, ADR number, lockfile) are resolved with deterministic post-checks, not trust in the model.
- ✅ Review budget unaffected; no history rewritten.
- ⚠️ **Semantic merge risk.** An L2 resolution can compile, pass review and still change behavior; the guards bound size and shape, not meaning. The human merge gate and CI remain the only semantic check.
- ⚠️ A model now writes into `CHANGELOG.md` and `docs/adr/` (human-owned by ADR-0021) through a named allowlist; this is a deliberate, scoped amendment of that rule, to be recorded in ADR-0021 when this ADR is accepted.
- ⚠️ A sweep over every open PR costs API calls and a PAT-authored commit per fix; fork PRs without `maintainer_can_modify` always end in L3.
- ⚠️ `mergeable_state` is asynchronous: a bounded retry can still end on `unknown`, so a conflict may be detected one trigger late.
