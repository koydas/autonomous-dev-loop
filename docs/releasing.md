# Releasing and Versioning (ADR-0045)

What other repositories pin is a commit of this repository, usually named by a tag `vMAJOR.MINOR.PATCH`. The contract between the pipeline and a caller is the interface of the five reusable workflows: `docs/workflow-interface.json`, generated by `node scripts/workflow_interface.mjs --write` and checked by the test suite and the changelog gate.

## What is a breaking change for a caller

Any of these needs a new **major** version and a `### Breaking` entry in the CHANGELOG:

| Change | Why a caller notices |
|---|---|
| An input or a secret removed, renamed, or made required (a new required input without a default) | The caller fails to start |
| An input whose type or default changes | Callers relying on the default behave differently |
| A permission ceiling that grows (a scope added, `read` → `write`) | The caller's job grants less than the workflow needs: it fails at startup |
| A new event or trigger a caller must declare | The pipeline stops reacting to it |
| A workflow file name a caller must keep (`codegen_workflow_file`, `autofix_workflow_file`) | Dispatch and run lookups miss |
| A configuration schema change: keys of `models.yaml`, groups of `labels.yaml`, the `protected-paths` grammar, the `review-evidence` format, `review-guidelines.md` limits | A repository's configuration stops loading (startup error) |
| Label names, artifact or checkpoint names, the `metrics` branch layout or the run-record schema | State written by an older version is no longer found |
| A higher minimum Node version or runner | The jobs fail |

Not breaking: prompt changes, default model changes, fixes, new optional inputs or secrets, new workflows, a smaller permission ceiling. A wider **protected-path floor** is listed under `### Security`: it blocks writes that were possible before, never a caller.

`node scripts/workflow_interface.mjs --base <snapshot of the previous release>` lists the interface changes that break a caller (exit 1); the rest of the table is judged by hand.

## Releasing

1. Compare with the last release: `git show v<previous>:docs/workflow-interface.json > /tmp/base.json && node scripts/workflow_interface.mjs --base /tmp/base.json`. Any line means a new major version.
2. In `CHANGELOG.md`, rename `## [Unreleased]` to `## [X.Y.Z] - <date>`, put what callers must do under `### Breaking`, and open a fresh empty `## [Unreleased]`.
3. Tag the commit of `main` with an annotated tag `vX.Y.Z` and push the tag. Do not create or move a floating tag (`v1`): the installation guide tells callers to pin commits, and a floating tag defeats it.
4. Publish the CHANGELOG section as the release notes, with the commit SHA callers should pin.

## Rules

- A published tag is never moved or deleted. A rule on the repository's tags (Settings → Rules) enforces it.
- A mistake is fixed by a new patch version, not by rewriting a release.
- The CI test suite fails when the workflows and `docs/workflow-interface.json` differ, and the changelog gate asks for an entry whenever a reusable workflow, a template or the snapshot changes: updating the snapshot is a deliberate, reviewed act.
